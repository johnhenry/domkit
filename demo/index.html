domkit

A live gallery of @johnhenry/domkit's modules, each running the real source from ../src/ in its own isolated iframe (so independent custom elements can coexist on one page without colliding). Nothing here is a mockup — every card is the actual module, actually running.

Four coherent clusters that used to be shown here were split out into their own packages, each with its own demo material: the "define a component" family → definable, responsive containers → respondable, the class-cycler family → cyclable, and mounts/hydratable → hydratable. This gallery now only shows what's still actually part of domkit.

Shadow DOM & lifecycle shadow-dom.element · internal-timer.component

shadow-dom.element

Deprecated alias for domable's simple-element shadowOpen.

internal-timer.component

A frame-paced tick emitter with pause/resume — a worked example of the disconnectedCallback lifecycle-symmetry fixes from the completeness audit.

Widgets

hotkey-modal.dialog.component

A native <dialog> opened/closed by a keyboard shortcut.

menu-component.component + hash.mjs

Keyboard-navigable stateful menu, synced to location.hash via its attach()/detach() companion.

stylable-select.component

A <select>-like element whose options can actually be styled.

tabbed-ui.component

Tabs/panels element, matched by position.

infinite-combo.component

A combo-box that loads more options on demand.

event-consumer.component

Declaratively wire event listeners without JS setup code.

code-color.component

Syntax-highlights its contents, re-highlighting on change.

Visual/canvas experiments animate-paths.component · xy-grapher · chernoff-face

animate-paths.component

SVG path animation — the domkit logo, animated.

xy-grapher

Known broken — component.mjs calls a genSVG() function that's never defined anywhere, so render() throws. Inherited from lib, predates this package. The demo used to silently mask this by accidentally registering chernoff-face's component under the xy-grapher tag (a copy-paste bug in the original demo.html) — fixed to register the real component, which surfaces the render bug instead of hiding it.

chernoff-face

Parametric faces as a data-visualization technique.

graph.component

Unimplemented placeholder — kept per the repo's no-deletion policy.

canvasrenderer.component, pixelshader.component, imagedata-emitter.component, and brains have no README or demo file yet (demo-grade experiments, carried over as-is from the original extraction) — not included here to avoid guessing at an undocumented API. See their source under src/.
